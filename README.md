# Proxy Bot для Telegram

Сайт: https://autotgproxyantidpi.onrender.com/  
Бот: https://t.me/autotgproxysuperbot  

Сервис собирает публичные MTProto-ссылки, безопасно разбирает их, удаляет дубликаты,
проверяет доступность и выдаёт пользователю свежий вариант через сайт или Telegram-бота.
Доступ бесплатный: страница `/subscribe` показывает тариф 0 ₽, а отдельная страница
`/connect_proxy` содержит список и персональный подбор прокси. Платёжных интеграций нет.

Важно: проверка выполняется из сети сервера. Она не может гарантировать доступность из
конкретной мобильной или домашней сети. MTProto не передаёт звонки Telegram; для звонков
приложение использует другие сетевые механизмы.

## Render (Орегон) и пользователь в России

Здесь есть два разных сетевых пути:

1. Render в Орегоне загружает списки и проверяет, отвечает ли MTProxy. Его миллисекунды —
   только серверный технический замер, а не пинг российского пользователя.
2. После нажатия ссылки Telegram подключается напрямую: устройство в России → российский
   оператор и его фильтрующее оборудование → выбранный MTProxy → Telegram. Пользовательский
   Telegram-трафик через Render не проходит.

Поэтому рекомендация сначала учитывает свежие отметки «работает/не работает» от целевой
аудитории за 14 дней, затем качество протокольного ответа, и только потом отклик из Орегона.
Один отрицательный отзыв сразу скрывает адрес только для автора; глобальное временное
исключение требует кворума разных пользователей. Небольшая выборка сглаживается, поэтому
один голос не создаёт ложные 0 или 100 процентов.

Без отдельного измерительного узла внутри российской сети сервер в Орегоне принципиально
не может самостоятельно доказать прохождение конкретного оператора. Сервис честно показывает
эту границу вместо обещания гарантированного обхода. Публичная часть описывает подход
абстрактно: проверка структуры секрета, ограниченные сетевые пробы, разнообразие источников,
свежесть и агрегированная обратная связь — без публикации эвристик отбора целиком.

Веб-подбор дополнительно использует только доступный браузеру технический профиль:
класс устройства, заявленный браузером тип/качество соединения, RTT, примерную пропускную
способность и режим экономии данных. Содержимое и история трафика не читаются. Telegram-бот
не получает такие сведения от Telegram, поэтому при первом персональном подборе просит
выбрать один из трёх профилей устройства и сети.

### Если адрес `onrender.com` не открывается

Код приложения не может изменить доступность домена Render на стороне оператора. Для
публичного запуска подключите собственный домен в Render Dashboard → Service → Settings →
Custom Domains, настройте DNS и после проверки домена задайте `BASE_URL` равным этому
HTTPS-адресу. Сайт больше не загружает шрифты или другие обязательные ресурсы со сторонних
доменов: HTML, CSS и JavaScript отдаются с одного адреса. Перед публикацией проверьте домен
из нескольких российских мобильных и домашних сетей; если сам маршрут до Render недоступен,
понадобится отдельный разрешённый публичный вход или зеркало у другого провайдера.

## Структура

- `main.py` — тонкий launcher для Render и локального `python main.py`;
- `app/main.py` — сборка aiohttp, Telegram-бота, webhook/polling и фоновых задач;
- `app/core/settings.py`, `app/core/auth.py` — конфигурация и безопасность;
- `app/proxy/` — источники, парсинг, декодирование, фильтры, ранжирование и worker;
- `app/db/schema.py` — PostgreSQL-репозитории и миграции;
- `app/web/` — публичный сайт, API и админка;
- `app/bot/handlers.py` — Telegram-сценарии и кнопки;
- `templates/`, `static/` — HTML/CSS/JS и админ-фронт;
- `tests/` — проверки парсинга, скоринга, каталога и auth.

## Локальный запуск

1. Создайте виртуальное окружение и установите зависимости:

   ```powershell
   py -m venv .venv
   .venv\Scripts\python.exe -m pip install -r requirements.txt
   ```

2. Скопируйте `.env.example` в `.env`, заполните обязательные значения.
3. Запустите ` .venv\Scripts\python.exe main.py`.
4. Проверьте тесты: `.venv\Scripts\python.exe -m unittest discover -s tests -v`.

Файл `.env` и любые ключи, локальные базы, логи и настройки IDE исключены из Git.
Реальные секреты храните только в локальном `.env` или в Environment хостинга.

## Развёртывание на Render

В корне есть `render.yaml`: один постоянно работающий Web Service в регионе Oregon,
команда сборки `pip install -r requirements.txt`, команда запуска `python main.py` и
health-check `/healthz`. Один экземпляр выбран намеренно: веб-сайт, бот и обновляющий
конвейер используют общий оперативный кэш. Результаты пользователей сохраняются в PostgreSQL.

Для production нужен платный `starter` или выше. Бесплатный Web Service засыпает после
15 минут без входящих запросов, поэтому вместе с ним остановятся webhook/бот и фоновое
обновление; бесплатный Render Postgres также не подходит для постоянного хранения.
Локальная файловая система Render эфемерна — хранить базу SQLite или секреты в файлах нельзя.

При ручной настройке Render:

- Region: `Oregon`;
- Build Command: `pip install -r requirements.txt`;
- Start Command: `python main.py`;
- Health Check Path: `/healthz`;
- Instances: `1`;
- переменные добавить в Dashboard → Service → Environment; `PORT` Render задаёт сам,
  а публичный адрес приложение берёт из `RENDER_EXTERNAL_URL`, если `BASE_URL` не указан.

## Переменные окружения

Обязательны для полного production-запуска:

- `BOT_TOKEN` — выдаёт `@BotFather` после `/newbot`;
- `BOT_USERNAME` — имя созданного бота без `@`;
- `TG_WEBHOOK_SECRET` — отдельный случайный секрет webhook (не `BOT_TOKEN`), например
  результат команды для `SECRET_KEY`; если не задан, безопасно выводится из `SECRET_KEY`;
- `DATABASE_URL` — строка подключения PostgreSQL от хостинга БД;
- `SECRET_KEY` — случайный секрет сессий, например результат
  `py -c "import secrets; print(secrets.token_urlsafe(48))"`;
- `BASE_URL` — публичный HTTPS-адрес развёрнутого приложения;
- `ADMIN_PASSWORD` — отдельный длинный пароль администратора;
- `ADMIN_PATH` — непредсказуемый сегмент адреса админ-панели.

Необязательны: `PORT`, `PROBE_REGION` (для этого развёртывания `us-oregon`),
`FETCH_PROXY` (только HTTP/HTTPS), `PROXY_CHANNELS`,
`PROXY_SOURCE_URLS` и параметры `PROXY_*` из `.env.example`. Не включайте
`FETCH_INSECURE_SSL=1`, кроме краткой диагностики собственного доверенного источника.

## В самом конце: какие локальные переменные нужны и где их получить

- `BOT_TOKEN` — открыть `@BotFather` в Telegram, выполнить `/newbot`, скопировать токен.
- `BOT_USERNAME` — username того же бота без символа `@`.
- `TG_WEBHOOK_SECRET` — сгенерировать локально:
  `py -c "import secrets; print(secrets.token_urlsafe(32))"`.
- `DATABASE_URL` — Render Dashboard → PostgreSQL → Connections → Internal Database URL;
  база должна находиться в том же регионе Oregon.
- `SECRET_KEY` — сгенерировать:
  `py -c "import secrets; print(secrets.token_urlsafe(48))"`.
- `BASE_URL` — локально оставить пустым для polling; на Render можно не задавать, если
  доступен автоматический `RENDER_EXTERNAL_URL`, либо указать `https://имя.onrender.com`.
- `ADMIN_PASSWORD` — придумать уникальную длинную парольную фразу или сгенерировать как
  `SECRET_KEY`; не использовать пароль Telegram/почты.
- `ADMIN_PATH` — придумать отдельный непредсказуемый сегмент без `/`, например
  `manage-` плюс случайная строка.
- `PROBE_REGION=us-oregon` — информационная метка расположения проверяющего сервера.
- `PORT=5000` — нужен только локально; Render предоставляет собственный `PORT`.

Остальные `PROXY_*`, `FETCH_PROXY`, `PROXY_CHANNELS` и `PROXY_SOURCE_URLS` необязательны:
начните со значений из `.env.example` и меняйте их только после проверки логов и нагрузки.
